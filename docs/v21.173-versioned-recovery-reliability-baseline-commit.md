# PHOENIX v21.173 — Versioned Recovery Reliability Baseline Proposal & Controlled Commit Governance

## Purpose
Create a versioned, rollback-bound recovery reliability baseline proposal from a human-approved impact preview and allow a controlled commit without activating it in runtime.

## Admission
Only v21.172 evidence in `approved-preview` state with human approval is accepted. Workspace, baseline ID and preview digest remain bound to the proposal.

## Versioning and bounds
- candidate version must equal previous version + 1
- rollback version/value must exactly reference the previous baseline
- previous/candidate values remain in the normalized 0.0–1.0 range
- maximum absolute candidate delta is 0.05
- duplicate source records fail closed

## Lifecycle
`review-required -> committed`

Invalid lineage, versioning, rollback binding, candidate bounds, missing approval or Risk Brain hard block results in `blocked`.

## Safety boundary
`committed` means versioned and human-approved only. This module does not activate the baseline, mutate consumers, change routing/policy, expand credentials/permissions, submit trades, move funds or actuate devices.
