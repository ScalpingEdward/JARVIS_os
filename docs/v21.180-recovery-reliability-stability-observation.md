# PHOENIX v21.180 — Recovery Reliability Stability Observation & Episode Closure Governance

## Purpose
Observe the recovered reliability consumer set after v21.179 completion and close the recovery episode only when stability remains above bounded thresholds.

## Admission
Only human-approved v21.179 `completed` evidence is admitted. Workspace, baseline ID, version and digest remain exact lineage bindings.

## Observation dimensions
Each expected consumer contributes:
- health state
- exact baseline match
- dependency satisfaction
- latency quality
- error quality
- confidence
- freshness

The module computes a deterministic aggregate stability score and residual risk.

## Lifecycle
`review-required -> closed`

Low stability, excessive residual risk, unhealthy consumers or baseline drift produce `degraded`. Invalid admission, incomplete consumer coverage, invalid metrics, duplicate source evidence or Risk Brain hard block fail closed to `blocked`.

Final episode closure requires explicit human approval.

## Safety boundary
Observation/governance only. `closed` means the recovered consumer set remained stable through the observation window and closure was human-approved. This module does not mutate consumers, activate or roll back baselines, change routing/policy, expand credentials/permissions, submit trades, move funds or actuate devices.
