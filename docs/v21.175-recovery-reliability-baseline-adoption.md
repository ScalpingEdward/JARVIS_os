# PHOENIX v21.175 — Recovery Reliability Baseline Adoption Authorization & Receipt Governance

## Purpose
Govern per-consumer adoption authorization for a staged recovery reliability baseline and require fresh evidence that the exact intended baseline was adopted.

## Admission
Only human-approved v21.174 records in `staged` state are admitted. Workspace, consumer, baseline ID/version/digest and rollback binding remain exact.

## Lifecycle
`review-required -> authorized -> receipt-required -> adopted`

Any invalid source, missing human authorization, rollback mismatch, Risk Brain hard block, receipt mismatch or replayed nonce fails closed to `blocked`.

## Receipt binding
A valid receipt must bind the same consumer/workspace/baseline ID/version/digest, assert successful adoption and carry a fresh unique nonce.

## Safety boundary
This module authorizes and verifies evidence only. It does not itself activate a baseline, mutate runtime consumers, change routing/policy, expand permissions/credentials, submit trades, move funds or actuate devices.
