# PHOENIX v21.165 — Reliability Baseline Adoption Authorization & Receipt Governance

## Purpose
Govern exact downstream consumer adoption of a staged reliability baseline using explicit human authorization and fresh adoption receipts.

## Admission
Only a v21.164 rollout record in `staged` state with the relevant stage human-approved may enter. Workspace, consumer ID, baseline ID, baseline version and baseline digest remain bound to the adoption record.

## Lifecycle
`review-required -> authorized -> receipt-required -> adopted`

Any invalid source, missing binding, missing approval, receipt mismatch, duplicate/replayed receipt nonce, duplicate source-consumer key or Risk Brain hard block fails closed to `blocked`.

## Receipt requirements
A valid receipt must exactly match:
- workspace
- consumer ID
- baseline ID
- baseline version
- baseline digest
- status `adopted`
- a fresh non-replayed receipt nonce

## Safety boundary
This module verifies authorization and receipt evidence only. It does not itself mutate a consumer, activate a baseline, change routing or policy, expand permissions/credentials, move funds or submit orders.
