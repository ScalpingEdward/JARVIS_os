# PHOENIX v21.193 — Versioned Recovery Reliability Baseline Proposal & Controlled Commit Governance

## Purpose
Convert a human-approved v21.192 impact preview into a versioned, auditable baseline proposal that can be committed only after a second explicit human approval.

## Admission
Only `approved-preview` evidence is admitted. Workspace, preview identity, baseline identity, previous version/value/digest and the previewed candidate value remain bound throughout the proposal.

## Versioning and rollback
The proposed version must equal `previous_version + 1`. Rollback version/value must exactly reference the previous baseline. Candidate values remain in `[0.0, 1.0]`, and the absolute delta from the previous value is capped at `0.05`.

## Lifecycle
`review-required -> committed`

Invalid lineage, replayed source/preview evidence, non-monotone versioning, rollback mismatch, out-of-range values, excessive delta or Risk Brain hard block produce `blocked`.

## Safety boundary
`committed` means a versioned baseline artifact was human-approved and recorded. It does **not** activate that baseline, change consumers, mutate runtime policy, expand permissions/credentials, submit trades, move funds or actuate devices.
