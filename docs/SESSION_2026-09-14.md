# Session 2026-09-14 -- Config Env-Prefix Bug + Media Pool Dedup

## Heute gefixt

- **`DATABASE_URL` wurde ignoriert**: `Settings` in `backend/app/config.py` liest Env-Vars
  standardmäßig mit `env_prefix="JARVIS_"`. `docker-compose.yml` und das Root-`.env` setzen
  die Postgres-Verbindung aber als plain `DATABASE_URL` (ohne Präfix) -- `Settings.database_url`
  fiel deshalb im echten Container-Deployment silently auf den Default `sqlite:///./jarvis.db`
  zurück, obwohl Postgres lief. Das war die eigentliche Ursache dafür, dass der Media Pool und
  die Instagram-Drafts keinen Neustart/Rebuild des `api`-Containers überlebten: die SQLite-Datei
  lag in der beschreibbaren Container-Schicht statt im `jarvis_data`-Volume und ist bei jedem
  Container-Rebuild verschwunden. Fix: `database_url: str = Field(default=..., validation_alias="DATABASE_URL")`.
- **Dieselbe Präfix-Lücke bei vier weiteren Feldern**: `app_name`, `environment`,
  `anthropic_api_key`, `openai_api_key` werden im Root-`.env`/`docker-compose.yml` ebenfalls
  unpräfigiert gesetzt (`APP_NAME`, `ENVIRONMENT`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`),
  während `backend/.env` (lokale Entwicklung/Tests) sie korrekt mit `JARVIS_`-Präfix setzt.
  Fix mit `AliasChoices("JARVIS_<NAME>", "<NAME>")` (JARVIS_-Variante zuerst), damit beide
  Schreibweisen funktionieren und kein bestehendes Setup bricht.
- **Dublettenprüfung auf `media_ref`**: `analyze_and_ingest()` in
  `backend/app/instagram_content/analyze_and_ingest.py` prüft jetzt vor der Vision-Analyse,
  ob `item.media_ref` bereits im Media Pool liegt (`pool_service.list_all()`). Falls ja, wird
  die Analyse komplett übersprungen und ein Ergebnis mit `success=true` und dem Hinweis
  "Already in the media pool -- skipped vision analysis." zurückgegeben, statt die Datei
  erneut (und ggf. kostenpflichtig) analysieren zu lassen.

## Vorheriger Stand (siehe auch SESSION_2026-09-13.md)

- `curate()` gruppiert jetzt primär nach `captured_at`-Kalendertag (lokale Zeit), dann
  `source_group`, dann `theme`; innerhalb einer Gruppe bleibt der Score-stärkste Hook vorn,

  `test_curate_elite_solo_threshold_is_a_hard_boundary` sichert die `>=`-Semantik ab.
