# PHOENIX v21.185 — Recovery Reliability Baseline Adoption Authorization & Receipt Governance

## Purpose
Authorize one staged consumer to adopt the exact recovery-reliability baseline and accept adoption only after fresh, exact receipt evidence is verified.

## Admission
Only a human-approved v21.184 source in `staged` state is admitted. Workspace, consumer, baseline ID/version/digest and rollback lineage remain bound to the adoption record.

## Lifecycle
`review-required -> authorized -> receipt-required -> adopted`

Invalid admission, missing human authorization, lineage mismatch, replayed nonce, stale evidence, negative adoption evidence or Risk Brain hard block fails closed to `blocked`.

## Receipt freshness
Each adoption receipt carries `evidence_age_seconds`. The record enforces a bounded `max_receipt_age_seconds`; stale receipts are rejected even when every other field matches.

## Safety boundary
This module authorizes and verifies evidence only. It does not activate a baseline, mutate a runtime consumer, change routing/policy/permissions/credentials, submit orders, move funds or actuate devices.
