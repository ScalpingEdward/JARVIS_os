# PHOENIX v21.183 — Versioned Recovery Reliability Baseline Proposal & Controlled Commit Governance

## Purpose
Turn an approved recovery-reliability feedback preview into a new immutable baseline proposal with explicit version, rollback and audit lineage.

## Admission
Only human-approved v21.182 `approved-preview` evidence is admitted. Workspace, preview ID, baseline ID, previous version/value/digest and source record remain bound.

## Versioning
The candidate version must equal `previous_version + 1`. Previous and candidate values must remain normalized to `0.0–1.0`, and absolute value change is bounded to `0.05`.

Rollback version/value are locked to the previous baseline. A deterministic candidate digest binds the new version to its preview and prior digest.

## Lifecycle
`review-required -> committed`

Invalid lineage, version gaps, rollback mismatch, excessive delta, duplicate source, missing human approval or a Risk Brain hard block fails closed to `blocked`.

## Safety boundary
`committed` means versioned and human-approved only. This module does not activate the baseline, mutate runtime consumers, change routing/policy, expand permissions/credentials, move funds, submit orders or actuate devices.
