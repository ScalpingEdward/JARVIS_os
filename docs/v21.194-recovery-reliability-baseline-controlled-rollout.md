# PHOENIX v21.194 — Recovery Reliability Baseline Controlled Rollout & Adoption Eligibility Governance

## Purpose
Determine whether a committed recovery-reliability baseline is eligible for a bounded, ordered adoption rollout without activating it automatically.

## Admission
Only human-approved v21.193 `committed` evidence is admitted. Workspace, baseline ID/version/digest and rollback lineage must remain exact.

## Rollout controls
The complete candidate consumer set must be covered exactly once across ordered rollout stages. Stage order is contiguous, consumer overlap is rejected, and every stage has a bounded exposure ceiling.

Eligibility requires explicit human approval. Every rollout stage then requires separate human approval in order.

## Lifecycle
`review-required -> eligible -> staged`

Invalid lineage, source replay, unsafe exposure, malformed stage order, consumer overlap or Risk Brain hard block fails closed to `blocked`.

## Safety boundary
Governance only. This module does not activate baselines, mutate runtime consumers, alter routing/policy, expand credentials/permissions, submit trades, move funds or actuate devices.
